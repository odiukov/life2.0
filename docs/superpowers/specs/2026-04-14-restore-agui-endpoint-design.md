# Restore `/agui` endpoint + `copilotkit-runtime` container

**Status:** Design
**Date:** 2026-04-14

## Problem

The frontend↔backend chat chain is broken on `master`. The React app uses
`@copilotkit/react-core@1.8` with `runtimeUrl="/copilotkit"`, which expects to
speak to a **Node** CopilotKit Runtime. The orchestrator instead mounts the
**Python** `copilotkit` SDK (`CopilotKitRemoteEndpoint`) at `/copilotkit`.
The v1.8 frontend can't drive that endpoint directly, so requests end in a
`INCOMPLETE_STREAM` / 404. An earlier attempt at the canonical Node-runtime
bridge was rolled back and is no longer recoverable from git.

## Goal

Restore the canonical CopilotKit v1.8 topology so the browser chat reaches
the existing `create_health_agent()` LangGraph graph and streams responses
back.

## Architecture

```
Browser (React + @copilotkit/react-core 1.8, runtimeUrl="/copilotkit")
    │
    ▼  HTTP /copilotkit
nginx  (agui-frontend container)
    │
    ▼  proxy_pass
copilotkit-runtime  (new Node container, port 4000)
  CopilotRuntime({
    agents: { default: new HttpAgent({ url: ORCHESTRATOR_AGUI_URL }) }
  })
    │
    ▼  AG-UI over HTTP SSE
orchestrator  (FastAPI, port 8000)
  /agui  ← add_langgraph_fastapi_endpoint(app, LangGraphAgent(graph=...))
    │
    ▼
create_health_agent()   (existing LangGraph ReAct graph with tools:
                         analyze_sleep / analyze_workout / analyze_nutrition /
                         sync_health_data / send_daily_briefing)
```

## Components

### 1. Backend — `orchestrator/app/main.py`

**Remove:**
- `from copilotkit import CopilotKitRemoteEndpoint`
- `from copilotkit.langgraph_agent import LangGraphAgent as _CopilotKitLangGraphAgent`
- `from copilotkit.integrations.fastapi import add_fastapi_endpoint`
- `class _HealthAgent` and its `dict_repr` override
- `_copilotkit_sdk = CopilotKitRemoteEndpoint(); _copilotkit_sdk.agents = [...]`
- `add_fastapi_endpoint(app, _copilotkit_sdk, "/copilotkit")`

**Add:**
```python
from ag_ui_langgraph import LangGraphAgent, add_langgraph_fastapi_endpoint

add_langgraph_fastapi_endpoint(
    app,
    LangGraphAgent(
        name="default",
        description="Personal health assistant with access to sleep, workout, and nutrition data",
        graph=create_health_agent(),
    ),
    path="/agui",
)
```

Everything else in `main.py` (`/chat`, `/chat/stream`, `/stats`,
`/health-summary`, `/agents`, `/briefing`, `/health`) is unchanged.

### 2. Orchestrator dependencies — `orchestrator/requirements.txt`

**Remove:** `copilotkit>=0.1.39,<0.2`

**Add:** `ag-ui-langgraph` (pinned to a version compatible with the existing
`langgraph` / `langchain-core` installed via `create_react_agent`). Use the
latest released version at implementation time; if install resolution fails,
fall back to the version that the rolled-back branch used (recoverable from
pip's transitive resolution — no hard pin in this spec).

### 3. New service — `copilotkit-runtime/`

```
copilotkit-runtime/
├── Dockerfile
├── package.json
├── package-lock.json      (generated by `npm install`)
└── server.js
```

**`package.json`** (essentials):
```json
{
  "name": "copilotkit-runtime",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": { "start": "node server.js" },
  "dependencies": {
    "@copilotkit/runtime": "^1.8.0",
    "@ag-ui/client": "latest",
    "express": "^4.19.2",
    "cors": "^2.8.5"
  }
}
```

**`server.js`** (shape):
```js
import express from "express";
import cors from "cors";
import { CopilotRuntime, copilotRuntimeNodeHttpEndpoint } from "@copilotkit/runtime";
import { HttpAgent } from "@ag-ui/client";

const ORCHESTRATOR_AGUI_URL =
  process.env.ORCHESTRATOR_AGUI_URL || "http://orchestrator:8000/agui";

const runtime = new CopilotRuntime({
  agents: { default: new HttpAgent({ url: ORCHESTRATOR_AGUI_URL }) },
});

const app = express();
app.use(cors());
app.use("/copilotkit", (req, res, next) =>
  copilotRuntimeNodeHttpEndpoint({
    endpoint: "/copilotkit",
    runtime,
  })(req, res, next)
);
app.get("/health", (_req, res) => res.json({ status: "ok" }));

app.listen(4000, () => console.log("copilotkit-runtime on :4000"));
```

**`Dockerfile`:**
```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY server.js ./
EXPOSE 4000
CMD ["node", "server.js"]
```

### 4. `docker-compose.yml`

Add:
```yaml
copilotkit-runtime:
  build: ./copilotkit-runtime
  environment:
    ORCHESTRATOR_AGUI_URL: http://orchestrator:8000/agui
  depends_on:
    orchestrator:
      condition: service_started
  restart: unless-stopped
```

Update `agui-frontend.depends_on` to also wait on `copilotkit-runtime`.
No host port exposure — it's only reached through nginx.

### 5. `agui-frontend/nginx.conf`

Change both `/copilotkit` `proxy_pass` targets to the Node runtime:

```nginx
location = /copilotkit {
    proxy_pass http://copilotkit-runtime:4000;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;
    proxy_set_header Connection '';
    proxy_http_version 1.1;
    proxy_set_header X-Real-IP $remote_addr;
}

location /copilotkit/ {
    proxy_pass http://copilotkit-runtime:4000;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;
    proxy_set_header Connection '';
    proxy_http_version 1.1;
    proxy_set_header X-Real-IP $remote_addr;
}
```

### 6. Frontend

No changes. `runtimeUrl="/copilotkit"`, `<CopilotChat>`, and the four
`useCopilotAction` handlers in `DashboardPage.tsx`
(`refresh_health_data`, `navigate_to_agents`, `highlight_agent`,
`show_metric_detail`) continue to work — CopilotKit's frontend action
plumbing flows through the Node runtime without needing changes here.

## Data flow (one user message)

1. User types in `<CopilotChat>`.
2. Frontend POSTs to `/copilotkit` (nginx).
3. nginx forwards to `copilotkit-runtime:4000/copilotkit`.
4. Node runtime invokes `HttpAgent` → POSTs AG-UI request to
   `orchestrator:8000/agui`.
5. `add_langgraph_fastapi_endpoint` invokes the LangGraph graph; tool calls
   fan out to sleep/workout/nutrition A2A agents via the existing `@tool`
   wrappers in `health_agent.py`.
6. AG-UI SSE events flow back up the chain: LangGraph → `/agui` → Node
   runtime → nginx → browser.
7. If the agent issues a frontend action call (e.g. `highlight_agent`),
   CopilotKit routes it to the matching `useCopilotAction` handler.

## Error handling

- **orchestrator unreachable from runtime:** `HttpAgent` surfaces the
  connection error; runtime returns 5xx; `<CopilotChat>` renders the error
  bubble. Nothing to do beyond the default.
- **LangGraph tool failure:** already handled inside `health_agent.py`
  tools — they catch and return a string describing the failure.
- **Runtime not ready when frontend starts:** nginx will return 502 until
  the runtime is up; `depends_on` + restart policy make this transient.

## Testing / verification

Manual, post-`docker compose up --build`:

1. `docker compose ps` — `copilotkit-runtime` is `Up`.
2. `curl -sf http://localhost:3000/copilotkit/health` via runtime is not
   exposed through nginx; instead verify reachability by:
   `docker compose exec agui-frontend wget -qO- http://copilotkit-runtime:4000/health` → `{"status":"ok"}`.
3. Open http://localhost:3000 in a browser. Send "how did I sleep last
   night". Expect the assistant response to stream and for the sleep agent
   to be consulted (verify via orchestrator logs showing a call to
   `agent-sleep:8001/tasks`).
4. Verify frontend actions by asking "highlight the sleep agent" — the
   Agents tab should open with the sleep card highlighted.
5. Confirm no new errors in `docker compose logs orchestrator copilotkit-runtime agui-frontend`.

- Adding tests for the Node runtime (it's a thin passthrough; covered by
  the end-to-end manual verification above).
